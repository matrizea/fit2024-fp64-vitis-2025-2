# 単体演算器の資源最適化

同じZCU104対象part、10ns clock、27% uncertainty、Vitis HLS 2025.2で、修正前と採用した修正後を比較しています。資源量・FmaxはHLS推定です。

原実装もゼロ・NaN・Inf・非正規化数を例外経路で処理することがユーザーから確認されています。例外分類の範囲は共通なので、対応範囲の広さを資源差の理由にはしません。返却bitや優先順位までの同一性は未検証です。

値は「論文 / 修正前 / 修正後」です。レイテンシはHLS topの報告値をそのまま使い、入力の受付間隔とは分けます。

| 演算器 | LUT | FF | DSP | top latency [cycle] | interval [cycle]（前→後） | 推定Fmax [MHz] |
|---|---:|---:|---:|---:|---:|---:|
| 加算 | 1,697 / 2,217 / 1,810 | 347 / 321 / 206 | 0 / 0 / 0 | 3 / 2 / 1 | 3→2 | 137.58 / 140.96 / 144.28 |
| 減算 | 1,789 / 2,219 / 1,812 | 460 / 321 / 206 | 0 / 0 / 0 | 3 / 2 / 1 | 3→2 | 137.17 / 140.96 / 144.28 |
| 乗算 | 577 / 795 / 571 | 123 / 124 / 80 | 8 / 9 / 9 | 2 / 1 / 1 | 2→2 | 142.63 / 137.06 / 149.16 |

修正前からのLUT変化:

- add_custom: -18.36%。論文値との差は +6.66%。RTL検証: Pass、1168呼出し。
- sub_custom: -18.34%。論文値との差は +1.29%。RTL検証: Pass、1168呼出し。
- mul_custom: -28.18%。論文値との差は -1.04%。RTL検証: Pass、1168呼出し。

## 採用した変更

- 加減算: 手書きの先頭ゼロ検出を幅対応のHLS intrinsicへ変更。符号を除く63bitを一括比較し、指数・仮数を別々に比較する回路を簡略化。
- 共通丸め: 53bit仮数に1を加えてcarryが出る場合、その値は厳密に2^53で下位bitはゼロ。この性質を使ってcarry時の幅広い仮数シフト・選択回路を除去。
- 乗算: 正確な106bit積を維持し、保持する53bitとguard/stickyを直接抽出。指数を13bitに限定し、同時には発生しない正規化carryと丸めcarryを一つの更新へ統合。

DSP8にする分割積の候補も合成しましたが、964LUT・162FFへ増加しました。採用したDSP9・571LUT版の方が全体の資源改善が大きいため、乗算DSP数には論文との差が1個残っています。候補と不採用理由: [加減算](../experiments/add/README.md)、[乗算](../experiments/mul/README.md)。

演算精度や特殊値対応を削って面積を減らす変更は採用していません。AMD公式モデルとの算術比較と、選択topを呼び出すRTL Cosimを実施しています。検証した入力集合における一致であり、全入力の形式的証明ではありません。

論文のlatencyの測定範囲を確定できないため、top latencyとの差をそのまま「論文より高速」とは解釈しません。現在のtop latencyと処理間隔はRTL Cosimでも確認しました。
